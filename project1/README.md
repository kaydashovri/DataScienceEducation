### Кейс и требования к реализации   
В рамках развлекательной программы у программистов-математиков встала потребность посмотреть и решить, а какие вообще существуют алгоритмы известной детской игры - угадай загаданное число. Напомним условия этой игры. Участвую два человека. Первый загадывает какое-то число от 0 до 100. Второй отгадывает. Чем меньше количество попыток тем лучше. 
Данный кейс решили автоматизировать путем написания соответствующей программы. 

Требования к реализации: 
1. Компьютер случайным образом загадывает целое число в диапазоне от 0 до 100 включительно.
2. Программа должна реализовать алгоритм угадывания числа.
3. После каждой попытки алгоритм получает информацию о том, больше или меньше загаданное число относительно текущей гипотезы.
4. Цель алгоритма — минимизировать количество попыток.
5. Реализация должна позволять многократный запуск для оценки средней эффективности алгоритма.

Критерий качества

Основная метрика — количество попыток, необходимое для угадывания числа при многократном тестировании - 10 000 запусков.

### Функционально-техническое описание реализации алгоритма 

### Идея алгоритма

Алгоритм угадывания использует стратегию управления диапазоном возможных значений. После каждой неудачной попытки диапазон сужается на основании подсказки «загаданное число больше/меньше», а следующая гипотеза выбирается как середина текущего диапазона (целочисленное деление).

### Переменные и структуры данных

- predict — текущее предположение (гипотеза), стартует случайным числом np.random.randint(1, 101).
- predict_lst_lower — история нижних границ диапазона. Инициализация: [1].
- predict_lst_upper — история верхних границ диапазона. Инициализация: [101] (как “верхняя граница + 1”, чтобы середина корректно работала на старте).
- count — счётчик попыток (увеличивается на каждой итерации цикла while до угадывания).

Практически в расчётах участвуют только последние элементы списков: predict_lst_lower[-1] и predict_lst_upper[-1]. Списки выступают как журнал изменений границ.

### Логика обновления диапазона
Цикл выполняется, пока predict != number.
1. Если number > predict (загаданное число больше гипотезы):
- текущая гипотеза становится новой нижней границей: predict_lst_lower.append(predict)
 - новая гипотеза вычисляется как середина между predict и текущей верхней границей: predict = (predict_lst_upper[-1] + predict) // 2
2. Если number < predict (загаданное число меньше гипотезы):
 - текущая гипотеза становится новой верхней границей: predict_lst_upper.append(predict)
 - новая гипотеза вычисляется как середина между текущей нижней границей и predict: predict = (predict + predict_lst_lower[-1]) // 2
3. Если number == predict:
 - цикл завершается, функция возвращает count.

### Границы диапазона
- Нижняя стартовая граница: 1
- Верхняя стартовая граница: 101 (используется как техническая верхняя граница, чтобы диапазон покрывал 1…100)

### Метрика эффективности

Результат функции — число попыток count, затраченных на угадывание одного заданного number.
При множественных прогонах (10 000 запусков) считается среднее количество попыток.


### Метрики тестирования и качества   
- Среднее число попыток на серии из 10 000 прогонов (фиксированный seed для воспроизводимости).
- Максимальное число попыток на серии прогонов (проверка худшего случая и отсутствия зацикливания).
- Стабильность результата: при одинаковом seed итоговая метрика должна повторяться.
- Важно про подсчёт попыток:
    - random_predict считает попытки “классически” (первая попытка = 1).
    - game_core_v2 и game_core_v3 возвращают 0, если число угадано с первой гипотезы (счётчик увеличивается только при несовпадении).
